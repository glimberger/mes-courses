# Research: One-Command Release

**R1 Where the code lives.** Decision: `apps/delivery`, new entry `src/composition/release.ts`, run with `tsx` like `ci.ts`; root script `release` forwards with `yarn workspace @mes-courses/delivery release`. Rationale: the rules (`release-rules.ts`, `semver.ts`), the `CommandRunner` and the `gh` adapters are already there; app and server stay untouched. Alternatives: a shell script (hard to unit test, shellcheck burden, would duplicate the rules); a new workspace (YAGNI).

**R2 Reuse of the rules (FR-012).** Decision: validation uses `tagVersion`, `parseSemver` and `compareSemver`; the final re-check before tagging calls the existing `evaluateRelease` with facts for the target: `tag` = `vX.Y.Z`, `appVersion` = version at the release commit, `onMain` = true (the commit is an ancestor of `origin/main`), `successfulWorkflows` from the observed runs, `productionVersion` from the existing `ChannelSource` + `parseManifest`. The early refusals (FR-006) run `evaluateRelease` too, on facts with the required workflows treated as satisfied, so the tag and production rules cannot drift from the gate. Alternative: call `releaseGate` as is; rejected because `appVersionAt` requires the checkout HEAD to be the tagged commit, while the local head may be newer than the bump commit.

**R3 Reading and writing the version.** Decision: the source of truth is `version: 'X.Y.Z'` in `apps/mobile/app.config.ts`. Pure domain functions `readAppVersion(source)` and `setAppVersion(source, next)` work on the file text (one regex on the `version:` property line; they throw when it matches zero or several lines). The remote version is read with `git show origin/main:apps/mobile/app.config.ts`, a commit's version the same way with `<sha>:`. Alternative: `expo config` (used by the gate): slow (npx) and needs a checkout at that commit.

**R4 Next-step decision (FR-011).** Decision: a pure `decideStep(version, state)` over the observed `ReleaseState`. Order: tag on the right commit -> done; main version equals target and runs all green -> tag; a run failed -> stop; runs pending -> wait for runs; main version old: PR merged -> re-fetch then evaluate again, PR open -> wait for merge, PR failed or closed -> stop, no PR -> open the bump. Nothing is stored locally.

**R5 Bump mechanics.** Decision: from the clean `main` equal to `origin/main`, `git switch -c chore/release-X.Y.Z` (or check out `origin/chore/release-X.Y.Z` when it exists), edit the file, commit `chore(release): bump the app version to X.Y.Z`, push with upstream, switch back to `main`, delete the local branch. The Git hooks run normally and are never skipped. Then `gh pr create` (or reuse `gh pr list --head`) and enable auto-merge on it through `gh` in squash mode with branch deletion. Alternative: a temporary `git worktree`; rejected as extra complexity, the clean-checkout precondition already makes switching safe.

**R6 Waiting.** Decision: poll every 30 s through an injected `sleep`, limit 90 min per wait, then stop with "run it again to resume". The PR wait reads `gh pr view --json state,statusCheckRollup,url,mergeCommit`; a failed check or a PR closed unmerged stops with the PR link. The run wait reads `gh run list --commit <sha> --workflow <name> --json conclusion,status,url` for each of `REQUIRED_WORKFLOWS`; the most recent run per workflow decides (success, failed, or pending; no run yet counts as pending). Alternative: `gh pr checks --watch` / `gh run watch` (blocking, hard to test).

**R7 Which commit gets the tag.** Decision: the squash commit of the merged bump PR (`gh pr list --head chore/release-X --state merged --json mergeCommit`), falling back to the newest first-parent commit of `origin/main` whose change of `app.config.ts` sets the target version (`git log -G`). The tag never goes on the later head. The tag is annotated (`git tag -a`) and pushed alone (`git push origin vX.Y.Z`); the `Release` run link comes from `gh run list --workflow Release --commit <sha>` polled briefly, falling back to the Actions page URL.

**R8 Stale base.** Decision: the next version is computed from the remote main version at start; that version is re-read before the bump commit; if it changed since the confirmation, stop.

**R9 Prompts.** Decision: `node:readline/promises` behind a `Prompter` port (`ask`, `confirm`); `--yes` skips only the confirmation, an absent argument still asks. Without a terminal and without argument, fail with usage instead of hanging.

**R10 Dry run (FR-007, SC-005).** Decision: the use case receives a `dryRun` flag; read-only observation still runs (`git fetch` updates remote-tracking refs only, documented); every mutating call goes through one `steps` object that, in a dry run, prints "would ..." instead, so a test asserts zero mutating calls. No wait is performed.

**R11 Prerequisites.** Decision: before any change, check `git` and `gh auth status`, branch is `main`, `git status --porcelain` empty, `git fetch origin`, `HEAD == origin/main`. Each refusal has its own message.

**R12 Testing without real tools.** Domain and use case against in-memory doubles with a scripted sequence of states and a fake sleep. Adapters: the `git` adapter against a temp repository with a local bare "origin"; the `gh` adapters against a fake `CommandRunner` asserting argument arrays and parsing canned JSON.
