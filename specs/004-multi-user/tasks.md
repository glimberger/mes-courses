**Tests**: REQUIRED (constitution Principle I, non-negotiable). There is no test-only task: every
task below holds its own test and its implementation. Inside a task, write the failing test first,
run it and confirm it fails for the expected reason, write the minimum code to turn it green, then
refactor with the suite green. Every commit leaves the whole suite green. Test names carry the
scenario id with the feature prefix, for example `"004 US4-2 a reset keeps the current password
working"`.

**Organization**: tasks are grouped by user story:

- **US1** (P1): the administrator invites someone;
- **US2** (P1): first sign-in with the temporary password;
- **US3** (P1): my data stays mine;
- **US4** (P2): I forgot my password;

- **US6** (P2): my account and my devices.

## Path Conventions

The Yarn workspaces monorepo of 001 and 003 ([plan.md](plan.md#source-code-repository-root)):

- the app is in `apps/mobile/src/`, and its `./testing` entry in `apps/mobile/test/`;
- the server is in `apps/server/src/{domain,application,adapters,composition,testing}/`;
- the shared package is `packages/sync-core/src/`;
- the tests that need the app and the server together (the HTTP adapters and the cross-stack
  scenarios) are in `tests/sync/src/`;
- the Pi files are in `deploy/`;
- the Detox journeys are in `tests/e2e/journeys/`.

Unit tests sit next to the code they cover as `*.test.ts(x)`, and stories as `*.stories.tsx`. The
stories and the journey to add are listed in
[contracts/ui-screens.md](contracts/ui-screens.md#stories-and-end-to-end-journeys).

## Rules that apply to every task

- **No test sends an email, reaches an SMTP provider, the Pi, or any address other than
  `127.0.0.1`** (Principle III). Time, ids, mail and password hashing come from the fakes
  `Clock`, `IdGenerator`, `FakeMailer` and `FakePasswordHasher` (cheap parameters).
- **French text only in the app's UI adapter and the server's `adapters/mail/`** (Principle X, v2.6.0:
  the mail adapter is a message-delivering adapter). Server routes return codes; the `create-admin`
  and `set-password` commands print English technical output.
- **No password, temporary password, email address, server URL, device name or client network
  address** in any log, error report or opaque id. The only user identifier in a report is the
  opaque `accountId`. Error report contexts are those of
  [ui-screens.md](contracts/ui-screens.md#error-reports-principle-viii).
- **Passwords are normalized to Unicode NFC** before they are counted, hashed or verified, on the app
  (`validateNewPassword`) and on the server (the hasher), and counted in code points
  ([research.md](research.md) R3). No trimming, no case folding.
- **Data separation** (FR-009): use cases and the domain never see an `account_id`. Data
  repositories are obtained only through `store.runForAccount`; directory work (accounts, devices,
  ended credentials, attempts) goes through `store.run`. Every identifier a client sends is read
  inside its own account ([research.md](research.md) R1).
- **Every server request that writes is one transaction**. A failure that must be recorded (a wrong
  password) is returned as an outcome, never thrown, because a throw rolls the record back.
- **Every new app screen or dialog** has loading, empty, error and success states where they apply
  (Principle IX), uses Paper and the shared module only (Principle V), and has a story for each
  state, added to `apps/mobile/src/adapters/ui/required-stories.ts`.
- **Pairing is removed, not kept beside sign-in**: the app side in US2 (T044), the server side in
  US2 (T046), once nothing depends on it. Until then, 003's pairing keeps working so that every
  commit stays green.
