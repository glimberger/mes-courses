**Purpose**: Check that every requirement and success criterion is precise enough to become an automated test or a written manual check, and that requirements, acceptance scenarios and contracts trace to each other (constitution Principles I, II and III), before implementation starts

**Feature**: [spec.md](../spec.md), with [contracts/driving-ports.md](../contracts/driving-ports.md), [contracts/driven-ports.md](../contracts/driven-ports.md), [contracts/ui-screens.md](../contracts/ui-screens.md) and [contracts/ui-validation.md](../contracts/ui-validation.md)

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

**Audience and depth**: reviewer, standard depth, used as a gate before `/speckit-implement`. Scope is the spec and its contracts; drift between the spec, plan.md and tasks.md is left to `/speckit-analyze`. Screen states and accessibility content are covered by [ux.md](ux.md), and data rules and persistence by [data.md](data.md); this checklist only asks whether those rules can be tested and traced.
